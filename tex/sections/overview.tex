\section{目的と読み方}

\subsection{公開判断と三つの状態}

本稿は，Egison core の source program が型付け可能であることを定める．公開する source
typing は $\mathsf{DDTyping}$ 一つだけであり，その内部を型の合成（synthesis）と検査
（checking）に分ける．signature $\Sighat$ は全判断で固定し，次のように省略する．
\[
\begin{array}{rcl}
q;S;\Omega;\Gamma\vdash e\Rightarrow\tau_{\mathrm{raw}}
  \dashv q';S';\Omega'
& &\text{synthesis},\\
q;S;\Omega;\Gamma\vdash e\Leftarrow\rho
  \dashv q';S';\Omega'
& &\text{checking}.
\end{array}
\]
ここで $q=(q_\kappa,q_\tau)$ は二 sort の fresh supply，$S$ は prevailing paired
substitution，$\Omega$ は capability variable の生成由来を記録する origin ledger である．
$q_\kappa$ と $q_\tau$ は，それぞれ次に生成する capability variable $\chi_{q_\kappa}$ と
target variable $\alpha_{q_\tau}$ の番号を持つ．どの規則も子を左から右へ調べ，出力
$q';S';\Omega'$ を次の子へ渡す．

closed wrapper は canonical initial supply $q_0$，恒等置換，空 ledger から開始し，最後にだけ
raw result を解決する．
\[
\mathsf{DDTyping}(\Sighat,\Gamma,e,\tau)
\Longleftrightarrow
\exists\tau_{\mathrm{raw}},q',S',\Omega',\mathcal O.\;
q_0;\mathsf{id};\varnothing;\Gamma\vdash
e\Rightarrow\tau_{\mathrm{raw}}\dashv q';S';\Omega'
\land \mathsf{TerminalAudit}(S',\mathcal O)
\land \tau=S'\tau_{\mathrm{raw}}.
\]
Lean では raw derivation と，それに構造を一致させた intrinsic Origin certificate を別 family
として持つ．$\mathcal O$はそのOrigin proofであり，terminal auditは同じproofを再帰的に辿る．
上の記法は三者を一つに合わせた公開判断を表す．追加factsを持つnodeは$\mathtt{let}$，matcher，
pattern constructorの三種である．

動的安全性の証明では，これら三つの推論状態を消去した内部 certificate
$\mathsf{RuntimeTyping}$ を使う．これは source acceptance を定める第二の型システムではなく，
runtime value typing と preservation の帰納法を状態履歴から切り離すための補助判断である．
source acceptanceと動的安全性に必要な構成要素の依存方向は
\[
\mathsf{infer\ success}\Longrightarrow\mathsf{DDTyping}
\Longrightarrow\mathsf{RuntimeTyping}
\Longrightarrow\mathsf{RuntimeSafety}
\]
である．最初の矢印は成功したtraversalの相互DD再構成とterminal validatorとして機械化済みである．
二番目はclosed signature・空contextに特殊化したOrigin derivation，終端 substitution に固定した
相互 state erasure，terminal auditの合成である．最後は内部certificateに対する
$\mathsf{CoreSafety}$の性質を模式的に表す．$\mathsf{DDTyping}$を入口として後二つを束ねた
source-facingな公開安全性定理は今後の接続である．

\subsection{Origin ledger が表すもの}

$\Omega(\chi)$ は次の三値を取る．ledger に明記されない variable は rigid として扱う．
\[
\begin{array}{c@{\quad}p{0.70\linewidth}}
\mathsf{rigid} & signature または入力 context に由来し，solve で動かせない；\\
\mathsf{renameOnly} & 外へ流れる producer であり，非 structural variable への rename だけを許す；\\
\mathsf{structuralFlexible} & constructor 内部または consumer demand の局所 variable であり，
export 前の structural solve を許す．
\end{array}
\]
expression scheme と pattern-function dual scheme の capability binder は，instance 時点から
$\mathsf{renameOnly}$ である．constructor／primitive instance と fresh consumer は
$\mathsf{structuralFlexible}$ として生成する．constructor export は公開 payload に残る像の
structural leaf だけを選択的に freeze する．matcher finalization は，最終 capability に現れる
全 DD-owned explicit ledger key の structural leaf を freeze するため，matcher 開始前に生成された
\texttt{fixMatcher} placeholder の owned leaf も対象になる．ordinary equality と one-way solve は，
いずれもその cut の ledger に対して admissible でなければならない．

\subsection{中心となる考え：producer と slot demand}

$\Matcher{\kappa}{\tau}$ は matcher を生成する producer type，
$\MatcherSlot{\kappa}{\tau}$ は matcher を消費する位置の expected type である．checking は常に
\[
\boxed{\text{synthesize }e\quad\longrightarrow\quad
\text{その出力 cut で一度だけ expected type と align する}}
\]
という一手順を取る．非恒等 coercion を選べるのは，その cut で resolved expected head が
$\mathsf{MatcherSlot}$ と判明している場合だけである．したがって coercion の場所は
$\mathtt{matchAll}$ など特定の構文に固定されない．例えば
\[
\mathit{use}:\MatcherSlot{\kappa}{\tau}\to\rho,
\qquad m:\Matcher{\kappa}{\tau}
\]
の下で $\mathit{use}\;m$ を型付けすると，関数適用が domain を先に確定し，引数 $m$ の
checking cut で producer と slot が対応付けられる．$\mathtt{matchAll}$ の matcher 引数と
matcher clause の next matcher も同じ checking を使う．「一度だけ」は導出木全体ではなく，
一つの checking cut ごとに一度という意味である．

resolved source と expected の組は次の表で分類する．
\begin{center}
\begin{tabular}{lll}
\toprule
resolved source & resolved expected & alignment \\
\midrule
$\Matcher{\kappa_p}{\tau_p}$
  & $\MatcherSlot{\kappa_c}{\tau_c}$ & matcher-to-slot \\
product of matchers
  & $\MatcherSlot{\kappa_c}{\tau_c}$ & product lift; matcher-to-slot \\
product of slots
  & $\MatcherSlot{\kappa_c}{\tau_c}$ & slot-tuple lift \\
$\MatcherSlot{\kappa_p}{\tau_p}$
  & $\MatcherSlot{\kappa_c}{\tau_c}$ & slot-to-slot equality \\
その他 & その他 & ordinary equality \\
\bottomrule
\end{tabular}
\end{center}
expected が型変数のままなら ordinary equality だけを行う．coercion のために未解決変数を
slot へ推測せず，ordinary equality の失敗後に別 branch を試す rollback も行わない．
